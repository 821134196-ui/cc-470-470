# 商场扶梯启停巡检与封控复开平台

管理楼层扶梯的运行方向、启停时段、班前检查、急停测试、围挡、故障报修、
维修到场、复检审批、复开确认与客流绕行提示。仅用 Python 标准库 + SQLite，
无第三方依赖。

## 快速开始

```bash
python3 run.py              # 重置演示库并写入样例场景，启动 Web（默认 127.0.0.1:8000）
python3 run.py --port 8080  # 换端口
python3 run.py seed         # 只写样例不开服务
python3 run.py reset        # 清空为初始数据（6 台全部停梯待检）
```

打开 `http://127.0.0.1:8000`，右上角切换登录角色（值班员 / 巡检员 / 维修工 / 客服）。

### 演示样例

| 设备 | 状态 | 说明 |
|---|---|---|
| E12-A | 运行中 | 班前五项全部合格 → 按当前方向版本正常开梯 |
| E23-A | 故障封控 | 24 小时内反复跳停 3 次自动封控并报修；围挡已设、维修到场、已超 SLA |
| E34-A | 故障封控 | 维修完成后复检被**另一名巡检员**退回，等待返工 |
| E23-B | 客流封控 | critical 客流自动停梯，围挡已设，客服已发布绕行提示 |

在「运行状态 → 演示注入」可模拟大客流 / 跳闸 / 故障码；对运行中设备注入
critical 客流会被进程内调度任务（10 秒一轮）自动停梯封控。

## 业务规则

**每日开梯**：巡检员逐项判定梯级 / 梳齿板 / 扶手带 / 照明（通过 / 失败 /
不适用）与急停装置（通过 / 失败）。五项全部「通过」检查单才完成；任一失败
或「不适用」均不放行。急停测试失败作为独立错误 `estop_test_failed`。

**启动**：仅值班员；需当日检查合格；命令携带 `(direction, direction_version)`，
与当前调度版本不符分别按「方向设置错误 / 版本过期」拒绝（`direction_mismatch`）。
开梯前先「准备启动」占用该梯 30 秒，两名值班员同时操作只有一人成功
（`start_conflict`，HTTP 409），含多线程实测。

**封控与复开**（故障流）：
封控 → 设围挡 → 报修 → 维修到场（无围挡拒绝，`barrier_missing`）→ 修复 →
巡检员提交复检 → **另一名**巡检员批准（本人审批拒绝，`duty_separation`）→
撤围挡 → 值班员复开确认 → 重新班前检查/启动。任一环节未满足就复开按
「提前复开」拒绝（`early_reopen`）。复检退回后维修返工、修复标记清空，
须重新复检批准。客流流：critical 自动封控，客流回落到 normal/low 才允许撤
围挡复开。

**反复跳停**：控制柜 24 小时窗口内跳闸满 3 次，第 3 跳自动转故障封控+自动
报修；窗口超时计数重置。

**维修延期**：SLA 默认 60 分钟；进程内任务每轮检查，超期写 `REPAIR_OVERDUE`
事件并在工单上显示超期分钟数（每 15 分钟节流一条告警）。

**职责边界**：值班员启停/改方向/复开；巡检员班前检查与复检（提交、审批须
不同人）；维修工到场/修复/返工；客服仅能发布与撤销绕行提示，任何设备操作
均被拒。

## 页面

- **楼层设备图**：F1–F4 各台扶梯用 ▲/▼ 直接标识当前方向（蓝上行 / 灰下行）；
  停梯围挡显示为红白**斜纹边界**（不是整块红色）；点击设备跳转工作台。
- **开梯清单**：每项三选一（通过 / 失败 / 不适用），急停二选一；显示当日
  结论与当前版本号，启动按当前版本提交。
- **运行状态**：控制柜读数（电流/带速/故障码）、客流密度、封控秒表、停梯/
  跳闸/改方向与演示注入；客服绕行管理。
- **封控计时 / 报修 / 复开**：封控时长、流程步骤条、报修工单（含本地故障
  照片）、SLA 超期、复检状态；底部**复开确认区**用红色虚线隔离并与普通按钮
  保持明显距离。
- **复检审批**：待批列表高亮「不能批准本人提交的复检」。
- **事件查询**：按设备 / 事件类型过滤的时间线，红色为异常、琥珀色为流程
  节点，全部状态动作均落事件表。

## 结构

```
escalator_platform/
  errors.py       # 七类独立业务错误 + 互斥/职责/状态错误
  db.py           # SQLite schema（staff/escalators/prechecks/lockdowns/
                  #   repair_orders/rechecks/detours/escalator_events）
  adapters.py     # 模拟控制柜、客流传感器（可注入跳闸/故障/大客流）
  service.py      # 状态机与全部业务规则
  scheduler.py    # 进程内任务：计划启停、跳闸/客流轮询、SLA 超期
  server.py       # 标准库 HTTP：JSON API + 静态页
  demo_data.py    # 演示人员与 6 台扶梯
  web/index.html  # 单页前端（商场白 / 机械银 / 安全红）
run.py            # 本地启动命令（serve / seed / reset）
tests/            # 34 个测试（领域规则 + HTTP 冒烟）
data/             # SQLite 库与 uploads/ 故障照片（运行时生成，git 忽略）
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：启动互斥（含两线程竞争）、检查完整性（漏项/失败/不适用/急停失败）、
封控阻断启停与方向变更、提前撤围挡与提前复开的逐阶段拦截、复检职责分离、
复检退回返工、反复跳停窗口、客流封控、维修延期告警、计划启停跳过、完整
故障流事件时序，以及 HTTP 层 409/403/400 错误码。

# 商场扶梯启停巡检与封控复开平台

管理楼层扶梯的运行方向、启停时段、班前检查、急停测试、围挡、故障报修、
维修到场、复检审批、围挡撤除复开与客流绕行提示。设备（控制柜/客流）与人员
均为演示数据。

纯 Python 标准库 + 原生前端，SQLite 持久化检查与状态事件，故障照片存本地目录，
进程内线程处理计划启停与维修超时。

## 一条命令启动

```bash
./run.sh              # 首次自动初始化演示数据，默认 http://localhost:8000
./run.sh --reset      # 清空历史重新开始
PORT=8123 ./run.sh    # 指定端口
```

命令行样例（正常开梯 / 跳停封控复开 / 复检退回三个完整场景，直接打印事件时序）：

```bash
python3 -m app.demo           # 三个样例依次执行
python3 -m app.demo normal    # 仅正常开梯（含启动互斥、版本校验）
python3 -m app.demo trip      # 仅跳停→封控→维修→复检→复开
python3 -m app.demo reject    # 仅客流封控→复检退回→提前复开阻断
```

测试：

```bash
python3 -m unittest discover -s tests -v
```

## 核心业务规则（均有独立错误码与测试）

- **开梯前置**：梯级、梳齿板、扶手带、照明、急停装置五项班前检查全部合格，
  且急停测试通过，才允许启动；检查漏项 / 失败 / 必检项选“不适用”均阻断启动。
- **启动互斥**：两名值班员不能同时启动同一扶梯（占用-提交-释放锁）。
- **版本提交**：方向配置带 `config_version`，方向变更后旧版本启动命令被拒，
  必须按当前版本提交；运行中不得改方向；方向与楼层物理关系矛盾时拒绝。
- **封控阻断**：故障 / 客流事件 / 急停测试失败 / 反复跳停触发停梯 → LOCKED、
  自动建工单并要求围挡；LOCKED 状态禁止任何启动，计划开梯也被阻断并记录事件。
- **围挡**：封控后 10 分钟宽限，未就位产生“围挡缺失”事件（幂等一次）；
  无围挡不得完成维修；封控卡片用红白斜纹边界表示，不是整块红色。
- **维修 SLA**：到场 30 分钟、修复 120 分钟，超时分别记录到场延期/维修延期事件。
- **反复跳停**：滚动 24h 窗口内 3 次跳停自动升级为大修锁定（REPEAT 工单）。
- **职责分离**：复检由巡检员提交、主管审批，**同人不能批准自己的复检**
  （先查同人再查角色）；退回后工单返回维修环节，可多次退回计数。
- **提前复开**：复开前必须复检审批通过、围挡仍在、当日检查仍合格，且二次确认；
  任一不满足都阻断并写 `REOPEN_BLOCKED` 事件。复开按钮在页面独立隔离区。
- **客服绕行**：仅封控中的扶梯可由客服发布/撤回绕行提示。

## 目录

```
app/db.py         SQLite 表结构（检查、工单、围挡、复检、绕行、照片、只追加事件流）
app/domain.py     常量、时钟、模拟控制柜/客流适配器
app/service.py    全部业务规则（PlatformService）
app/scheduler.py  进程内线程：计划启停、围挡宽限、维修 SLA、运行轮询
app/seed.py       演示人员/扶梯
app/server.py     标准库 HTTP：JSON API、multipart 照片上传、静态文件
app/demo.py       三个命令行样例
web/              前端（index.html / styles.css / app.js）
data/             运行期 SQLite 与 photos/ 故障照片（不入版本库）
tests/            32 个 unittest：互斥、检查完整、封控阻断、职责分离、事件时序等
```
